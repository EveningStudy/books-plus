## 本轮修复

1. 阅读中远端更新不可见、打开书使用旧快照。
2. 初始化/索引/排版/空闲关闭被保存成新进度，造成回退或回声。
3. 相同时间戳的合并取决于枚举顺序，ISO 时区字符串直接比较不可靠。
4. 远端状态刚到达时，局部收藏修改可能丢掉其他字段。
5. 本机备份丢失后，旧/空的自己快照可能覆盖云端完整快照。
6. 正文比书目晚到时丢失已声明修订，误弃有效 CFI。
7. 未确认回写挡住更新的远端会话，页首对齐后长期冻结导出。
8. Books 前台阅读时被自动回写打断；仅打开书抬高旧位置时间；普通阅读覆盖云端完成状态。
9. 连续文件事件无限重置 debounce，及周期运行中到达事件被漏到下次补查。

## 接力使用条件与限制

- Mac 保持 Books+ helper 运行；所有设备选择**同一个云端书库**的本地副本，等待云盘把最新 JSON 和正文下载到本机。
- Books+ 本地到达检测约 5 秒；Mac helper 文件事件合并最长约 1.5 秒，30 秒补查。云盘服务器传输、睡眠和 Books 自己落库没有固定延迟保证。
- Apple Books 往往在关闭书籍窗口后保存；切设备前建议先关闭该书。自动回写可能打开 Books；它在前台时暂缓跳转，可主动点「在 Books 中继续」。
- 严格接续使用相同正文的原生 EPUB CFI。PDF/百分比、批注、完成状态只从 Books 导出；不反向注入 Books。DRM 无法移植；转换器版本不同的 CFI 不保证兼容。
- 页面对齐或章首空 CFI 不能证明精确定位，仍可能需要人工核对。第一份对齐保存隔离为回声，之后不同且更晚的独立保存可恢复导出。
- 尚未实测第二台个人 Windows 电脑与各家真实云盘服务器之间的网络传输、另一台 Apple 设备、实际重新登录、全部输入格式。CI Windows 运行与本地 Windows 目录模拟分别记录，不能互相替代。
- Mac 为 Apple Silicon 的 ad-hoc 本地签名包；没有 Developer ID / Apple 公证。Intel/universal 构建未在本机验证。
